## Findings

### CB-P1-r1-D1: the probe left out one of the 14 non-CICS programs (class D, about a number)

- **Evidence:** at CardDemo 59cc6c2, `ls app/cbl | wc -l` gives 31 and `grep -l 'EXEC CICS' app/cbl/* | wc -l` gives 17, so 14 files have no CICS. `grep -L 'EXEC CICS' app/cbl/*` lists COBSWAIT.cbl, which is missing from `per_program` in run `P1-feasibility-cobc-syntax-1` (`programs_tried: 13`). `research/P1.md:16`, `research/P1.md:80` and `SPEC.md:79` say "10 of 13 non-CICS programs". The PR body says the same.
- **Re-run:** `cobc -fsyntax-only -I app/cpy -std=ibm` (GnuCOBOL 3.2.0, gnucobol3 3.2-4build1, unpacked by the reviewer) on all 14 files: 11 pass. COBSWAIT passes. The same three failures as run 1: CBEXPORT:68, CBIMPORT:40, CUSTREC.cpy:6.
- **Fix (applied in r2):** appended row `P1-feasibility-cobc-syntax-2` to `results/P1-feasibility.jsonl` (14 tried, 11 ok, machine read at run time). Run 1's row is kept. research and SPEC now say "11 of 14" and cite run 2.

### CB-P1-r1-D2: COBSWAIT's assembler dependency is not in the risks (class D, minor)

- **Evidence:** `app/cbl/COBSWAIT.cbl:38` has `CALL 'MVSWAIT'`. `MVSWAIT` lives in `app/asm/MVSWAIT.asm`. GnuCOBOL cannot build assembler, so the program passes a syntax check but cannot link or run without a stub. `research/P1.md` section 6 does not list this.
- **Fix (applied in r2):** added a risk row with two mitigations: a recorded stub under `fixtures/`, or leaving COBSWAIT out of the run set and saying so. P2 picks one. B8 also notes it.

### CB-P1-r1-D3: SPEC says P5 runs on ubuntu-latest, but state.json sends it to the box (class D, minor)

- **Evidence:** `SPEC.md:44` says "so P5 runs on ubuntu-latest". `.forge/state.json` has `"needs_box": ["P5"]`, and DECISIONS.md (P1, last row) keeps that routing on purpose.
- **Fix (applied in r2):** SPEC now says P5 *could* run on ubuntu-latest, that `needs_box` still routes it to the box, and that the routing is forge's call.
