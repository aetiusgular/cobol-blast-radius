## Findings

### CB-P2-r1-E1: the cobc dialect that defines ground truth is not in any contract (E, above minor)

- **Evidence.** `grep -rn -- '-std=' contracts/ scripts/setup.sh tests/red/` finds one hit outside the build flag `-std=gnu17`: `tests/red/test_p3a_generate.py:38`, which hard-codes `-std=ibm`. `contracts/runset.json`, `runset.md` and `ground-truth.md` say how the harness compiles but name no dialect. `seams.md:11` says only "checks with `cobc -fsyntax-only`". The P1 probe (`research/P1.md:16`) and P2's split check (`results/P2-split-syntax.jsonl`, `command`) both used `-std=ibm`.
- **Why it matters.** `-std` loads a dialect configuration. That configuration decides which programs compile, and so which changes are excluded as `compile_failure`. It also sets the runtime semantics that produce the golden outputs. With no dialect in a contract, P3a's harness could build with another dialect than the generator test enforces, and two correct P3a implementations could produce different ground truth. Nothing in a results row would show the difference. Contracts are frozen after P2, so fixing this later would take a Request for integration and P4.
- **Fix (applied in round 2).** `contracts/runset.json` and both mini run sets now pin `"cobc_flags": ["-std=ibm"]`. `runset.md` defines the field: every ground-truth `cobc` call uses these flags, and the harness adds only `-I` and its output flags. `ground-truth.md` (`compile`) and `seams.md` (`generate`) point to it. `test_p3a_generate.py` reads `rs["cobc_flags"]` instead of hard-coding the flag, so the assertion is unchanged and stronger. `check-contracts.py` fails when a run set lacks `cobc_flags`. A copy of `contracts/runset.json` without the field printed `FAIL contracts/runset.json: cobc_flags must be ...`.

### CB-P2-r1-E2: the heldout guard on `radius/` only catches literal change ids (E, minor)

- **Evidence.** `scripts/check-isolation.py` fails only when a file under `radius/` contains a heldout id such as `S-001`. `eval.md` rule 1 says P3b "does not read the heldout rows". A radius test that loads `contracts/split.jsonl` and selects `split == "heldout"` would pass the check.
- **Fix (applied in round 2).** The check also fails when any file under `radius/` contains the word `heldout`, in any case. Code that reads the split filters on `"dev"`. `eval.md` rule 1 and `seams.md` say so. When `# heldout` was appended to `radius/predict.py`, the check printed `FAIL radius/predict.py names the heldout split`, and that file was then restored.
