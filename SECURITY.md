# Security

Open items, rendered into the README in P6. Severity: high, medium, low.

| ID | Severity | Item | Owner | Workaround | Status |
|---|---|---|---|---|---|
| T-1 | low | `ci` runs the PR's own copy of `ci.yml`, so a PR that edits it could post statuses with the workflow token. | Tony | `forge/guard` (base copy) fails any PR that touches `.github/`, and review reads the diff. | open |
| T-2 | low | gitleaks honours inline `gitleaks:allow` comments; a PR could mark a line as allowed. | Tony | Review greps the diff for `gitleaks:allow`. | open |
| T-3 | low | Under the box's `landlock` profile, TCP rules name ports, not addresses: the model port and the proxy (ephemeral) port range are open to any host, not only 127.0.0.1. | Tony | Only for projects with `eval_boundary: landlock`; the box's nftables rules and the proxies' own allowlists still apply. | open |
| G-1 | medium | The ground-truth harness (`groundtruth/harness.py`) compiles and runs the COBOL programs of the tree it is given, with a change applied, as the calling user, with no sandbox. Its environment drops `COB_*` and `DD_*` variables but keeps the rest (`PATH`, `HOME`). A change from outside the frozen split or the generator could run arbitrary code through a COBOL program. | Tony | P4 decided that `approve` and `deny` never call the harness, so a proposed change is predicted, never run. The harness runs only from `eval` (an operator's command over a split file) and `scripts/p4-runset-probe.py` (no change). The P5 box runs evals inside srt with no network but the model endpoint. | open |
| G-2 | low | A changed program that loops while writing could fill the disk before the per-step timeout ended it. | P4 | Since P4, every file a step's program writes is capped at 256 MiB (`RLIMIT_FSIZE`, `STEP_FILE_CAP`), stdout and stderr included; past it the step abends (`tests/integration/test_mini.py`). A program can still open many files under the cap; run in a work folder on a disk with headroom. | mitigated |
| R-1 | low | The predictor (`radius/`) parses the edited text of a proposed change in memory. It runs nothing, opens no network connection and reads no file outside the root it is given (`radius/source.py` `Tree.read`), but a crafted source can make it slow or large: COPY nesting is capped at 12 levels, but a huge OCCURS count gives a large bitmask, and the fixed-point loop is capped at 200 rounds per program. | P6 | It runs as the caller's own CLI on the caller's machine, not as a service, so the cost falls on the caller. P6 lists it under what the build does not cover. | open |
| A-1 | low | The ledger's hash chain catches an edited, inserted, reordered or deleted entry, but not a deleted last entry or a chain rewritten consistently by someone who can write the ledger folder. | P6 | `verify` returns `head_sha256` (`contracts/ledger.md` since P4). Keep it outside the ledger (a commit or the PR) and check it with `verify --expect-head`. | open |
| A-2 | low | `decided_by` on an approval record is whatever the caller passes with `--by`. It is not an authenticated identity. | Tony | Since P4 the record also carries `applied_as`, the OS account from the effective uid, so the ledger shows which local account applied each change. Anyone who can write the ledger folder can still rewrite it consistently (A-1). Signing entries would need a key and a key holder, which is Tony's call (BUILD_OUTLINE section 2, rule 4). | open |
| A-3 | low | `approve` and `deny` refuse a run set whose jobs or programs are missing under `--root`, or whose `carddemo_commit` is not the tree's git `HEAD` (CB-P3c-r3-S1). A run set that names the right tree but leaves jobs out still predicts a narrower radius. | P6 | The approval record carries `runset_sha256`, so the ledger shows which run set each decision used; compare it with `contracts/runset.json`. | open |
