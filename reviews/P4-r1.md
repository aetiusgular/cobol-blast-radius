## Findings

### CB-P4-r1-S1: `check_runset_fits` checks only that named jobs and programs exist, so a run set with wrong `copy_dirs` (or one that names a subset) still narrows the radius (S, minor)

- **Evidence.** `approval/allowlist.py:122-144` checks that each listed job file and program exists under the root, and checks `carddemo_commit` only when the root is the top of its own git checkout. It never reads `copy_dirs` or `libraries`, and it never checks that the run set lists every job in the tree. On a scratch copy of `fixtures/mini`, with `fixtures/mini/changes/field-label.json` and the rules `[{"pattern":"MINI.SUMFILE","kind":"dataset","action":"deny"},{"pattern":"**","action":"allow"}]`:
  ```
  approve --runset fixtures/mini/runset.json                         rc=4  deny
  approve --runset <mini run set, jobs=[MINIJOB1], programs=[MINIRPT]>  rc=0  approve allow, datasets []
  approve --runset <mini run set, jobs=[], programs=[], program_dirs=["nope"]>  rc=0  approve allow, datasets []
  predict --runset <mini run set, copy_dirs=["nope"]>  datasets [] programs []   (every job and program present)
  ```
  The applied tree then holds `VALUE 'TOTAX'` in `app/cpy/MINICNST.cpy`, so a change that writes a denied dataset was applied.
- **Why minor.** It is the same class as CB-P3c-r3-S1, which was rated minor: the caller has to pass a run set that does not match the tree, the default `--runset` matches the default `--root` and is checked by `scripts/check-contracts.py`, and the caller can already write `--root` (SECURITY.md A-2). The record's `runset_sha256` shows a non-default run set in the ledger. The subset case is disclosed as SECURITY.md A-3 (low).
- **Fix (P6, A-3's owner).** In `check_runset_fits`, require every job file under the tree's JCL folder to be in `jobs` or `excluded_jobs` (the rule `check-contracts.py` already applies to CardDemo), and require each of `copy_dirs`, `program_dirs` and each `libraries` dir to exist under the root. Or refuse any `--runset` whose sha256 is not that of `contracts/runset.json` or a fixture run set unless a flag is passed. Add a CLI test for the `copy_dirs` case.

### CB-P4-r1-D1: SECURITY.md A-3 and `contracts/allowlist.md` describe the remaining gap as only "leaves jobs out" (D, minor)

- **Evidence.** SECURITY.md A-3 says "A run set that names the right tree but leaves jobs out still predicts a narrower radius." `contracts/allowlist.md` ("Approval record") says the run set "must describe the tree" and lists only the job, program and commit checks. The `copy_dirs` case in S1 has every job and program present and still predicts an empty radius.
- **Fix.** Widen A-3 to "leaves jobs out or points `copy_dirs`, `program_dirs` or `libraries` elsewhere", or close it with the S1 fix. This is not about a number, so it does not block (section 5).
